# Конфігурація

Проєкт описується одним файлом `tr_pipeline.toml` (або `.json` з тією ж структурою).
Усі відносні шляхи рахуються від теки конфігу. Невідомий ключ — одразу помилка (захист від опечаток).

## Верхній рівень

| Ключ | За замовчуванням | Опис |
|---|---|---|
| `game` | `""` | назва гри для промптів |
| `target_lang` | `"uk"` | код мови перекладу; визначає назву мови в промптах і мовні перевірки |
| `workdir` | `"tr_work"` | робоча тека: чекпоінти, логи, запуски редактури, вивід |
| `provider` | `"openai"` | активний профіль із `[providers.*]` або просто тип провайдера |

## `[source]` — звідки брати рядки

| Ключ | Опис |
|---|---|
| `path` | файл або glob (`text/**/*.json`). Якщо файлів кілька, id стає `відносний/шлях::id` |
| `format` | `auto` (за розширенням), `json`, `jsonl`, `csv`, `tsv`, `po` або `пакет.модуль:фабрика` |
| `records` | для JSON: крапковий шлях до списку/мапи записів, напр. `"strings"` або `"data.lines"` |
| `id` | поле ідентифікатора (за замовч. `id`; для PO — `msgctxt\|msgid`). Якщо поля немає — ключ JSON-мапи або номер рядка |
| `scene` | поле сцени; `@file` — ім'я файлу. Для кількох файлів без `scene` сценою стає ім'я файлу |
| `scene_pattern` | регекс, що витягує сцену з поля `scene` (або з id): група 1, якщо є |
| `speaker` | поле мовця (імʼя/ключ персонажа з глосарію) |
| `context` | список полів з поясненнями для моделі (коментарі розробників, `extracted` для PO) |
| `max_length` | поле з максимальною видимою довжиною рядка |
| `target` | поле з уже наявним перекладом — буде імпортовано, а не перекладено наново |
| `skip_pattern` | регекс по основному тексту: такі записи не перекладаються (службові рядки) |
| `tag_lang` | мова, теги якої є технічним контрактом (за замовч. перша мова) |
| `encoding` | кодування файлів (`utf-8-sig`; BOM зберігається як був) |
| `delimiter` | роздільник CSV |
| `options` | довільна таблиця для плагін-форматів |

**Шляхи до полів** крапкові: `dialogue_context.speaker.id`. Через `|` задаються альтернативи —
береться перша непорожня: `"speaker_id|speaker"`.

### `[source.langs]` — мови-джерела

Порядок важливий: **перша мова — першоджерело змісту**, решта — довідкові.

```toml
[source.langs]
ja = "jp"          # японська з поля "jp" — головне джерело
en = "en"          # англійська — довідка (і контракт тегів, якщо tag_lang = "en")
```

Мова може лежати в окремому файлі, записи зʼєднуються за id:

```toml
[source.langs.en]
field = "text"

[source.langs.ja]
path = "text/ja/{relpath}"   # {relpath}, {stem}, {name} — від поточного файлу джерела
field = "text"
# format, records, id — як у [source], за потреби
```

Для мов, що не є `tag_lang`, теги в промпті вирізаються, щоб модель орієнтувалась лише на один набір маркерів.

## `[output]` — куди писати

| Ключ | Опис |
|---|---|
| `path` | шаблон шляху: `{workdir}`, `{relpath}`, `{stem}`, `{name}`. За замовч. `{workdir}/output/{relpath}` |
| `field` | поле для перекладу. За замовч. `source.target`, інакше поле першої мови (заміна оригіналу) |

> Не пишіть вивід поверх джерела, якщо переклад замінює поле оригіналу: наступне читання побачить уже перекладений текст.

## `[glossary]`

```toml
[glossary]
characters = ["glossary/characters.json"]
terms = ["glossary/*.json"]
max_terms = 30
max_characters = 12
```

Формат файлів довільний — поля шукаються за типовими іменами:

| Що | Кандидати полів |
|---|---|
| оригінал | `source`, `term`, `original`, `<мова>`, `name_<мова>`, `en`, `name_en`, `name`, `key` |
| переклад | `<target_lang>`, `name_<target>`, `preferred_<target>`, `target`, `translation`, `translated` |
| синоніми | `aliases`, `alias`, поля інших мов джерела; `"A / B"` розбивається |
| опис | `description`, `description_<target>`, `note`, `role`, `voice`, `category` |
| стать | `gender`, `sex` (`male/female/чоловіча/жіноча/m/f/...`) |
| заборонені варіанти | `forbidden`, `consistency_rules[].variant` (для `audit`) |

Контейнер: список, обʼєкт зі списком `terms`/`characters`/`entries`/`glossary`/`items`, або мапа `"Shion": "Шіон"`.
Запис із `gender` вважається персонажем. У промпт потрапляють лише терміни, що трапляються в текстах пакета,
і персонажі-мовці.

## `[tags]` — технічні теги

| Ключ | За замовч. | Опис |
|---|---|---|
| `patterns` | `[]` | додаткові регекси тегів рушія |
| `defaults` | `true` | вбудовані: `<...>` (HTML, Unity rich text, TMP, UE rich text), `{...}`, printf `%s %1$d`, `\n \r \t` літерально |
| `newlines` | `true` | справжні переноси рядків теж маркери (кількість рядків зберігається) |
| `strict_order` | `false` | вимагати той самий порядок тегів (для рушіїв, де порядок критичний) |

Приклади: `'\[[a-z_]+=[^\]]*\]'` (`[flag=x]`), `'#\w+#'`, `'\$[A-Z_]+\$'`, `'&[a-z]+;'` (HTML-сутності).

## `[validate]`

| Ключ | За замовч. | Опис |
|---|---|---|
| `forbid` | за мовою | регекси, що не мають траплятися у видимому тексті. Типово: CJK для не-CJK мов; для `uk` ще `ыэёъ` |
| `latin` | `true` для кириличних мов | латинські слова, яких немає в оригіналі, — помилка |
| `allowed_latin` | `[]` | дозволені латинські слова (`HP`, `OK`, назви брендів) |
| `max_length` | `true` | перевіряти ліміт довжини з `source.max_length` |

## `[translate]`

| Ключ | За замовч. | Опис |
|---|---|---|
| `provider` | — | профіль лише для перекладу |
| `max_chars` | 6000 | бюджет символів запиту (система + пакет) |
| `max_records` | 40 | максимум рядків у пакеті |
| `attempts` | 3 | спроб на рядок (невдалі повертаються з описом помилки) |
| `workers` | 1 | паралельні запити |
| `group_by_scene` | `true` | тримати сцени разом у порядку файлу |
| `merge_scenes` | `true` | дрібні сцени можуть ділити пакет (з позначкою сцени) |
| `dedupe` | `true` | однакові рядки одного мовця перекладаються один раз |
| `reuse` | `true` | брати переклад ідентичного рядка з чекпоінту |
| `log_responses` | `true` | писати сирі відповіді в `responses.jsonl` |

## `[proofread]`

`provider`, `max_chars` (12000), `attempts` (2), `workers` (1). Див. [редактура](proofreading.md).

## `[prompt]`

| Ключ | Опис |
|---|---|
| `rules` | додаткові правила проєкту (текст) |
| `rules_file` | те саме з файлу |
| `translate_file` | повна заміна системного промпту перекладу |
| `proofread_file` | заміна спільної частини промпту редактури (інструкції стадій додаються) |
| `note_language` | мова нотаток редактора (за замовч. мова перекладу) |

У власних промптах доступні підстановки `{game}`, `{target}`, `{sources}`, `{priority}`, `{rules}`, `{note_language}`.
Маркери `{0}` та JSON-дужки не чіпаються.

## `[providers.NAME]`

Див. [провайдери](providers.md).

## Робоча тека

```
tr_work/
  translations.jsonl   чекпоінт: останній рядок для id — чинний
  errors.jsonl         рядки, що не пройшли після всіх спроб (наступний translate спробує знову)
  responses.jsonl      сирі відповіді моделей
  stats.json           запити / токени по provider:model
  audit.json           звіт audit
  proofread/<run>/     запуски редактури
  output/              результат export
```
