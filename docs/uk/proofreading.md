# Трирівнева редактура

[English](../en/proofreading.md) | **Українська**

Вичитка йде трьома незалежними проходами, кожен зі своїм промптом і перевіркою відповіді:

| Стадія | Що робить модель | Рішення |
|---|---|---|
| `meaning` | звіряє переклад з оригіналом: пропуски, додавання, заперечення, числа, учасники, ідіоми, жарти | `ok` / `issue` / `needs_review` + нотатка |
| `edit` | редагує мову з урахуванням нотатки `meaning`: кальки, синтаксис, рід, звертання, глосарій | `keep` / `change` (+ новий текст) / `needs_review` |
| `verify` | незалежно перевіряє запропонований текст проти оригіналу, попередньої версії й нотаток | `accept` / `reject` / `needs_review` |

Рядки з `needs_review` не йдуть на наступну стадію. У гру потрапляє лише те, що отримало `accept`.

## Швидкий шлях

```bash
gameloc proofread prepare               # snapshot усіх перекладених рядків
gameloc proofread run                   # meaning → edit → verify, стадії просуваються автоматично
gameloc proofread export                # accepted → чекпоінт зі статусом proofread
gameloc export                          # у файли гри
```

`prepare` приймає `--scene` (вичитка по главах) і `--include-proofread` (повторно вичитати вже вичитане).
Без явного шляху створюється `gameloc_work/proofread/<дата-час>`, інші команди беруть останній запуск.

Для редактури можна взяти сильнішу модель, ніж для перекладу:

```toml
[proofread]
provider = "claude"
max_chars = 12000
workers = 4
```

## Як це влаштовано

```
gameloc_work/proofread/20260924-101500/
  snapshot.json               незмінний знімок: тексти, чернетки, промпти стадій
  meaning/packets.jsonl       пакети (batch_id = хеш вмісту)
  meaning/responses/<id>.json перевірені відповіді (з хешем промпту)
  meaning/invalid/            відхилені відповіді з причиною
  edit/ ...  verify/ ...
  review.json                 після export: усе, що потребує людини
```

- Кожна відповідь перевіряється: той самий `batch_id` і стадія, кожен id рівно раз, допустиме рішення,
  непорожня нотатка; для `change` — маркери тегів і повна валідація тексту. Невдала відповідь
  повертається моделі з описом помилки (`attempts`).
- Відповіді привʼязані до хешу промпту: якщо пакет змінився, стара відповідь не буде тихо використана.
- `export` пропускає рядки, чернетку або оригінал яких змінили після snapshot, — вони йдуть у `review.json`.
- Запуск можна переривати будь-коли: `run` відповідає лише на пакети без відповіді.

## Ручний режим (будь-який чат)

Коли API недоступний або хочеться вичитати критичну сцену самому чи в веб-чаті:

```bash
gameloc proofread next meaning            # пише next-<batch>.txt з повним промптом
# вставте текст у чат, збережіть відповідь у answer.json
gameloc proofread submit meaning <batch> answer.json --reviewer "Олена"
gameloc proofread advance edit            # коли meaning завершено
gameloc proofread status
```

Ручні та автоматичні відповіді можна змішувати в одному запуску.

## Розвʼязання решти

`export` лишає в `review.json` рядки, які стадії не змогли погодити (verify `reject`, `needs_review`, провалена перевірка).
`resolve` — четверта стадія для них: модель бачить оригінали, поточний текст, відхилену пропозицію, причину
й усі нотатки рецензентів і пише фінальний текст (`final` + translation, валідується як `change`) або `needs_review`.

```bash
gameloc proofread export                 # пише review.json
gameloc proofread resolve                # відповідає на пакети resolve і знову робить export
gameloc proofread next resolve           # або вручну / зовнішнім агентом: next + submit
```

Перед `resolve` можна прибрати з `review.json` рядки, які має вирішити людина. Рядки, чия чернетка змінилася
після знімка, пропускаються.

## Після редактури

`review.json` містить для кожного непройденого рядка причину, оригінал, чернетку, пропозицію і нотатки всіх стадій.
Зручний цикл для людини:

```bash
gameloc sheet-export review.csv --scene chapter1
# перекладач правит колонку translation
gameloc sheet-import review.csv           # валідація + статус manual
```

`gameloc audit` перевіряє весь чекпоінт (теги, скрипти, латиниця, довжина, заборонені варіанти з глосарію),
`audit --terms` додатково показує терміни глосарію з оригіналу, яких немає в перекладі (за початком слова, тож
відмінкові форми зараховуються); `audit --requeue` відправляє проблемні рядки на повторний переклад.

Знайти рядок: `gameloc show <id> --context 3` показує його із сусідами, оригіналами й перекладами;
`gameloc grep 'регекс'` шукає в оригіналах і перекладах.
